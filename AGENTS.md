# AGENTS.md

Rules for every coding agent working on Accent Mirror, the factory included. Read this before planning a change.

## What the app is

Accent Mirror helps an English learner hear and see how their prosody differs from a native speaker's. You record a
phrase, and the app lines your take up against a native recording, then shows stress, rhythm and pitch side by side,
with a few concrete differences to work on. Everything runs on the device. Native macOS first, iOS right after.

## Layout

- `AccentMirror/`: the macOS app target. Keep it thin: windows, views and wiring only.
- `Packages/AccentKit/`: all the logic, as a local Swift package, platform-neutral (macOS 26 and iOS 26). Anything
  you can test without UI goes here.
- `project.yml`: the XcodeGen spec. `AccentMirror.xcodeproj/` is generated by `make generate` and git-ignored.
- `specs/`: the spec queue (`specs/README.md`). `docs/`: reference notes, including `docs/thresholds.md`.
- `scripts/`: guard scripts CI runs.

### Module map

| Module | Owns | Depends on |
|---|---|---|
| `AMCore` | Domain types, the analysis contract, thresholds | nothing (Foundation only) |
| `AMCapture` | Recording and importing takes | AMCore |
| `AMAlignment` | Word timings (replayed or live ASR) | AMCore |
| `AMPitch` | F0 tracking behind `PitchTracker` | AMCore |
| `AMProsody` | Stress, rhythm and intonation features | AMCore, AMAlignment, AMPitch |
| `AMWarp` | Time-warping a take onto the native model | AMCore, AMPitch |
| `AMScoring` | Comparison against the native band, diff rows | AMCore, AMProsody, AMWarp |
| `AMLibrary` | Starter phrases and saved takes | AMCore |
| `AMPipeline` | Wires the stages into one analysis | all of the above |

Dependencies point inward, towards `AMCore`. A module never imports one that isn't in its row; `AMCore` imports
nothing but Foundation. No module in `AccentKit` imports AppKit or UIKit (`make check-ui-frameworks` enforces it).
The app target depends on `AMPipeline`.

## On-device only

- No network calls at runtime. No analytics, no accounts, no telemetry, no crash reporters.
- The core pipeline must work with networking denied, and its tests must prove that where it matters.

## Dependencies

- Apple frameworks first (Accelerate/vDSP, AVFoundation, Core ML, Speech).
- A new SPM dependency needs a written reason, a pinned version and a GPL-3.0-compatible licence.
- Never Essentia (AGPL). Never AudioKit for pitch: pitch is our own YIN/pYIN on Accelerate/vDSP behind a
  `PitchTracker` protocol.

## Data

- Never commit Common Voice, the Speech Accent Archive or any other local-only or non-commercial corpus. They live
  under the git-ignored `eval-local/`. CI fails if they appear (`scripts/check-local-corpus.sh`).
- Committed audio is CC BY or CC0 only, with attribution in a manifest and in `THIRD_PARTY_NOTICES.md`.

## Model weights

- Never committed, never Git LFS. Fetched at build time, pinned to an upstream commit (never `main`) and a SHA-256;
  the build fails on a mismatch.
- Each model's LICENSE/NOTICE lives in the repo next to its manifest, under `Resources/Models/`.

## CI

- ASR never runs in CI: tests replay recorded word timings.
- CI never launches the app, never uses the microphone, never runs UI tests.
- CI runs on GitHub-hosted `macos-26` with Xcode pinned. Never self-hosted runners (public repo, fork PRs).

## Tests

- Swift Testing (`@Test`, `#expect`) in the package. Test behaviour, not internals.
- `make test` must pass with no new warnings, and `make build` must not add warnings from our code.
- Tunable numbers live in `docs/thresholds.md` and `AMCore/Thresholds.swift`. They are tuned only on the tuning
  split, never on held-out clips, and never lowered quietly: a change says why in the PR.

### UI tests run in the test VM, never on Raph's screen

App-hosted tests (today `make test-ui`, which is `make screenshots`: every UI fixture rendered in light and dark,
plus the blank-frame check) open real windows and take over the screen they run on. On Raph's Mac they run in the
headless Tart test VM (`wg-ci`, Xcode 26.2, shared with WriteGood), through the installed Manufacture CLI:

```sh
make test-ui-vm      # the screenshot run in the VM (also: make screenshots-vm)
make test-vm         # AccentKit's package tests in the VM
make test-ui-vm UI_TEST_FLAGS=-only-testing:AccentMirrorScreenshots/ScreenshotTests   # just the affected tests
```

- Agents (the factory, Claude Code in Herdr) never run `make test-ui` or `make screenshots` on the host; both refuse
  for them. Never set `AM_HOST_UI_OK` (Raph's own override). Running a UI test from Xcode is Raph's, by hand.
- The VM has one lock and runs are serial, CI-style jobs included. Run only the affected tests while iterating, keep
  one VM command per builder at a time, and never start a second while one runs.
- Read the last line, which starts with `Tests:` or `VM:` (through make any failure exits 2). `Tests: passed`;
  `Tests: failed (rc 1)` is a real failure: fix it. `VM: not running …` (exit 2), `VM: busy …` (exit 3: retry later)
  and `VM: sync failed …` (exit 4) are not test failures: say so in the PR and never fall back to the host. Never
  start, stop or reset the VM; that's Raph's.
- Results come back to `.factory/vm-results/<stamp>/` (git-ignored): the `.xcresult`, and the screenshot PNGs in
  `<stamp>.xcresult.attachments/ui-shell/`.
- The guest builds from the synced tree with `make generate`, so code must compile with the Xcode 26.2 SDK.
- `make test` (package tests, no windows) and `make build` / `make check` stay fine on the host and in CI.

## Raph-only areas

Agents never touch these: code signing, team ID, provisioning, entitlements, the hardened runtime, notarization,
release builds and uploads, the `NSMicrophoneUsageDescription` strings, Sparkle, `.factory/`, `.github/`, `.claude/`
and the `Makefile`. Bundling third-party weights or recordings waits until the licence check clears them. Never
merge, never push to `main`, never flip a spec to `Ready`.

## CTO decisions (2026-11-23)

1. Model weights are fetched at build time, pinned by SHA-256. No LFS.
2. Apple SpeechAnalyzer is an optional comparator only: never download or install its assets, and keep a test that
   proves no network is used.
3. Pitch is our own YIN/pYIN behind `PitchTracker`.
4. Stress detection is measured against human-labelled actual stress and must beat the CMUdict baseline on
   misplaced-stress clips, on held-out eval clips. Whisper word spans get ~80 ms padding. Never lower a threshold
   quietly.
5. CI runs on GitHub-hosted `macos-26` with Xcode pinned, never on self-hosted runners.

## Commands

```sh
make generate   # xcodegen generate
make build      # macOS app, unsigned
make test       # swift test on AccentKit
make check      # build + test + corpus guard (and its self-test) + no AppKit/UIKit in AccentKit
make test-ui-vm # UI/screenshot tests in the test VM (agents: never host test-ui / screenshots)
make test-vm    # package tests in the test VM
```

## Commits

- Short messages that explain why.
- No `Co-authored-by` trailers, no Claude/AI credit lines.
- No secrets, team IDs or personal paths (anything under a home folder) in any committed file.
